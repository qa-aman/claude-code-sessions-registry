Claude Code — Named Sessions Registry Bootstrap

A self-contained, zero-dependency HTML file. Hand it to a fresh Claude Code session and it will install ccs — a tiny session manager that lets you name, list, and resume your Claude Code sessions across many terminals without ever using the /resume picker. Works on macOS and Linux. No secrets, no external services, no GitHub repos needed.

1. What this is

If you run 5+ Claude Code sessions in parallel across projects, the built-in /resume picker becomes unusable — every session looks like a hex ID, and you forget which is which.

ccs solves this with four small pieces:

  1. A single bash script at ~/.local/bin/ccs — the CLI.
  2. A global registry JSON at ~/.claude/named-sessions.json — the source of truth.
  3. A statusline script at ~/.claude/statusline-ccs.sh — surfaces the Claude Code PID at the bottom of every window, which is what ccs add needs.
  4. A per-project markdown file at <project>/.claude/claude-sessions-registry.md — auto-created the first time you register a session in that project. The table inside is rewritten by ccs on every change, so you can browse "what sessions exist for this project" right in your repo.

That's the whole system. No daemons, no databases, no cloud sync. Everything is local files you can read and edit.

6. MERGE STATUSLINE + SESSION RETENTION INTO settings.json (non-destructive)
   Two keys get merged here. `statusLine` powers the PID display. `cleanupPeriodDays`
   stops Claude Code from auto-deleting session transcripts after the default
   30 days — without it, `ccs open` eventually has nothing to resume.
   Run this exact python3 snippet (remember: the << below is HTML-encoded as
   `&lt;&lt;` in the source — decode it to `<<` before pasting to bash):

       python3 - <<'PY'
       import json, os, pathlib
       p = pathlib.Path(os.path.expanduser("~/.claude/settings.json"))
       data = {}
       if p.exists():
           try: data = json.loads(p.read_text())
           except Exception:
               print("settings.json exists but is invalid JSON. Aborting merge — fix it manually.")
               raise SystemExit(1)
       changed = False
       existing = data.get("statusLine")
       target = {"type": "command", "command": "bash ~/.claude/statusline-ccs.sh"}
       if existing == target:
           print("statusLine already pointing at ccs — nothing to do.")
       elif existing:
           print("Existing statusLine found:", existing)
           print("Leaving it untouched. To switch, edit ~/.claude/settings.json by hand.")
       else:
           data["statusLine"] = target
           changed = True
           print("Added ccs statusline to ~/.claude/settings.json")
       if "cleanupPeriodDays" in data:
           print("cleanupPeriodDays already set:", data["cleanupPeriodDays"], "— leaving it untouched.")
       else:
           data["cleanupPeriodDays"] = 3650
           changed = True
           print("Set cleanupPeriodDays=3650 — session transcripts kept ~10 years instead of 30 days.")
       if changed:
           p.parent.mkdir(parents=True, exist_ok=True)
           p.write_text(json.dumps(data, indent=2))
       PY

   Tell the user: a Claude Code RESTART is required for the new statusline
   to take effect.

7. ADD ~/.local/bin TO PATH (shell-aware, idempotent)
   Pick the right shell rc:

       case "${SHELL:-}" in
         */zsh)  RC="$HOME/.zshrc" ;;
         */bash) RC="$HOME/.bashrc" ;;
         */fish) RC="" ;;
         *)      RC="$HOME/.profile" ;;
       esac

   If RC is empty (fish or unknown):
     print: "Add ~/.local/bin to your PATH manually in your shell config."
   Else:
     touch "$RC"
     grep -q '\.local/bin' "$RC" || echo 'export PATH="$HOME/.local/bin:$PATH"' >> "$RC"

   Tell the user: open a new terminal (or `source "$RC"`) before running ccs.

8. SMOKE TEST
     ~/.local/bin/ccs list
   Expected output: "No sessions registered. Use: ccs add <name> <pid>"
   If you see a Python traceback or "command not found", stop and paste the
   full error to the user.

9. TELL THE USER WHAT TO DO NEXT (print verbatim)

     ✓ ccs is installed.
     ✓ Statusline is configured.
     ✓ Session retention extended (cleanupPeriodDays: 3650) — Claude Code
       won't auto-delete your sessions after the default 30 days.
     → RESTART CLAUDE CODE so the statusline shows up.

     After restart, the bottom of your Claude Code window will show:

         ⊡ <project-name>  pid:54057

     The number after `pid:` is what `ccs add` needs.

     To register THIS Claude Code session, open a separate terminal and run:

         ccs add my-session 54057          # substitute your real PID

     Or, from inside Claude Code itself, prefix with `!`:

         ! ccs add my-session 54057

     The first `ccs add` in a project auto-creates a registry file at:

         <current-project>/.claude/claude-sessions-registry.md

     Common commands:
         ccs list            # all named sessions with live/idle status
         ccs pids            # all running Claude PIDs
         ccs open <name>     # resume by name (run outside Claude Code)
         ccs sync            # rewrite all per-project registry tables

Stop conditions:
- A required tool is missing → ask the user to install it.
- Step 6 reports "settings.json exists but is invalid JSON" → DO NOT try to
  fix it yourself. Tell the user the file is malformed and ask them to fix
  it (or move it aside) before re-running the bootstrap.
- A step produces an unexpected error → paste the failing command and error
  output, then ask the user how to proceed.
- Never invent paths, PIDs, or content. Never skip the smoke test.

3. The ccs session manager — full embedded script

This is the complete source of ~/.local/bin/ccs. It auto-discovers projects from each session's working directory — there are no hardcoded paths. Copy this entire block into ~/.local/bin/ccs and chmod +x.

#!/usr/bin/env bash
# ccs — Claude Code Sessions manager
# Name, list, and resume Claude Code sessions across terminals.
# Per-project registry files are auto-created on first `ccs add` in that project.

REGISTRY="$HOME/.claude/named-sessions.json"
SESSIONS_DIR="$HOME/.claude/sessions"
HISTORY="$HOME/.claude/history.jsonl"

# Embedded template — written on first `ccs add` inside a new project.
read -r -d '' REGISTRY_TEMPLATE << 'TEMPLATE_EOF' || true
# Claude Code Sessions Registry

Name, list, and resume Claude Code sessions for this project without using `/resume`.
Global registry file: `~/.claude/named-sessions.json`

---

## Registered Sessions

> Auto-synced on every `ccs add`, `ccs rename`, `ccs remove`, and `ccs sync`.

| Name | PID | Status | Created | Last Used | Msgs | Description |
|---|---|---|---|---|---|---|
| — | — | — | — | — | — | No sessions registered for this project yet |
---

## Quick Reference

| Command | What it does |
|---|---|
| `ccs list` | Show all named sessions with live/idle status, created date, last used, message count |
| `ccs pids` | Show all running Claude processes with PIDs |
| `ccs open <name>` | Resume a session by name (run outside Claude Code) |
| `ccs add <name> <pid>` | Register a session using its PID (shown in the statusline) |
| `ccs add <name> <pid> "<desc>"` | Register with a custom description |
| `ccs update <name> "<desc>"` | Update description of an existing session |
| `ccs rename <old> <new>` | Rename a session |
| `ccs remove <name>` | Delete a session from the registry |
| `ccs sync` | Force-rebuild every project's registry table from the global JSON |
| `ccs sessions` | Browse last 30 sessions from history |

---

## Notes

1. `ccs open` must be run **outside** an active Claude Code session.
2. All other commands work both in terminal and inside Claude Code via `!`.
3. `○ idle` means the terminal process ended but the session is still resumable.
4. Session names are case-sensitive. Use lowercase kebab-case.
5. The Registered Sessions table is auto-maintained — never edit it manually. Run `ccs sync` if it looks stale.
6. Description is auto-populated from the session's first message if not provided.
TEMPLATE_EOF

# Ensure a registry file exists for the given project path. Creates the dir+file
# from the embedded template only if missing. Safe to call repeatedly.
ensure_project_md() {
  local project_path="$1"
  [ -z "$project_path" ] && return 0
  local md="$project_path/.claude/claude-sessions-registry.md"
  if [ ! -f "$md" ]; then
    mkdir -p "$project_path/.claude"
    printf '%s\n' "$REGISTRY_TEMPLATE" > "$md"
    echo "Created $md"
  fi
}

# Rewrite each project's Registered Sessions table with only its own sessions.
# Projects are discovered from the `project_path` stored on each registry entry.
sync_md() {
python3 << 'PYEOF'
import json, os, glob, re, datetime, collections

REGISTRY     = os.path.expanduser("~/.claude/named-sessions.json")
SESSIONS_DIR = os.path.expanduser("~/.claude/sessions")
HISTORY      = os.path.expanduser("~/.claude/history.jsonl")

with open(REGISTRY) as f:
    data = json.load(f)
all_sessions = data.get("sessions", {})

# Group sessions by their stored project_path.
by_project = collections.defaultdict(dict)
for name, info in all_sessions.items():
    pp = info.get("project_path", "")
    if pp:
        by_project[pp][name] = info

# Single pass through history for last_used + msg_count.
last_used = collections.defaultdict(int)
msg_count = collections.defaultdict(int)
if os.path.exists(HISTORY):
    with open(HISTORY) as f:
        for line in f:
            try:
                e = json.loads(line.strip())
                sid = e.get("sessionId", "")
                ts  = e.get("timestamp", 0)
                if sid:
                    msg_count[sid] += 1
                    if ts > last_used[sid]:
                        last_used[sid] = ts
            except Exception:
                pass

# PID map from session files.
pid_map = {}
if os.path.isdir(SESSIONS_DIR):
    for f in glob.glob(SESSIONS_DIR + "/*.json"):
        try:
            with open(f) as fh:
                d = json.load(fh)
            pid = os.path.basename(f).replace(".json", "")
            pid_map[d.get("sessionId", "")] = pid
        except Exception:
            pass

def fmt_ts(ts):
    if not ts:
        return "-"
    return datetime.datetime.fromtimestamp(ts / 1000).strftime("%d-%m-%Y %H:%M")

def is_alive(pid):
    try:
        os.kill(int(pid), 0)
        return True
    except Exception:
        return False

def build_table(project_sessions):
    lines = [
        "## Registered Sessions",
        "",
        "> Auto-synced on every `ccs add`, `ccs rename`, `ccs remove`, and `ccs sync`.",
        "",
        "| Name | PID | Status | Created | Last Used | Msgs | Description |",
        "|---|---|---|---|---|---|---|",
    ]
    if project_sessions:
        for name, info in project_sessions.items():
            sid     = info.get("id", "")
            pid     = info.get("pid") or pid_map.get(sid, "-")
            created = info.get("created_at", "-")
            desc    = info.get("description", "-")
            lu      = fmt_ts(last_used.get(sid, 0))
            msgs    = str(msg_count.get(sid, 0))
            alive   = "● live" if pid != "-" and is_alive(pid) else "○ idle"
            lines.append(f"| `{name}` | {pid} | {alive} | {created} | {lu} | {msgs} | {desc} |")
    else:
        lines.append("| — | — | — | — | — | — | No sessions registered for this project yet |")
    return "\n".join(lines)

# Rewrite each project's md file.
for project_path, sessions in by_project.items():
    md_file = os.path.join(project_path, ".claude", "claude-sessions-registry.md")
    if not os.path.exists(md_file):
        continue
    new_table = build_table(sessions)
    with open(md_file) as f:
        content = f.read()
    updated = re.sub(
        r"## Registered Sessions.*?(?=\n---)",
        new_table,
        content,
        flags=re.DOTALL,
    )
    with open(md_file, "w") as f:
        f.write(updated)
    print(f"Synced {project_path} ({len(sessions)} session(s))")
PYEOF
}

cmd="$1"

if not sessions:
    print("No sessions registered. Use: ccs add <name> <pid>")
else:
    print()
    hdr = ("NAME".ljust(28) + "STATUS".ljust(8) + "PID".ljust(7) +
           "CREATED".ljust(13) + "LAST USED".ljust(17) + "MSGS".ljust(6) + "PROJECT")
    print("  " + hdr)
    print("  " + "-" * 105)
    for name, info in sessions.items():
        sid     = info.get("id", "")
        pid     = info.get("pid") or pid_map.get(sid, "-")
        alive   = "● live" if pid != "-" and is_alive(pid) else "○ idle"

                sid = entry.get("sessionId")
                if sid and sid not in sessions:

                pass

print()
print("  " + "#".ljust(4) + "DATE".ljust(17) + "SESSION ID".ljust(38) + "PROJECT".ljust(22) + "FIRST MESSAGE")

4. Configure the statusline to show the PID

Claude Code lets you define a custom statusline via ~/.claude/settings.json. The script below prints ⊡ <project> pid:<claude-pid> at the bottom of every Claude Code window. The PID it shows is exactly what ccs add <name> <pid> expects.

The statusline script

Save this to ~/.claude/statusline-ccs.sh, then chmod +x ~/.claude/statusline-ccs.sh.

#!/usr/bin/env bash
# Claude Code statusline for ccs.
# Reads the session JSON Claude Code pipes in on stdin, extracts cwd, and
# prints "⊡ <project-basename>  pid:<claude-code-pid>".
#
# Capture $PPID into a named variable on the FIRST line of execution.
# Rationale: $PPID is the process that invoked this bash — i.e. the running
# `claude` process — and that is the same PID Claude Code uses as the filename
# in ~/.claude/sessions/<pid>.json. Saving it before any pipes/subshells run
# locks in the value and avoids any chance of confusing it with a child PID,
# a shell-job PID, or the sessionId from the stdin JSON.
claude_pid="$PPID"

input=""
if [ ! -t 0 ]; then input=$(cat); fi

cwd=""
if [ -n "$input" ]; then
  cwd=$(printf '%s' "$input" | python3 -c "
import json, sys
try:
    d = json.load(sys.stdin)
    print(d.get('cwd', ''))
except Exception:
    pass
" 2>/dev/null)
fi

project=$(basename "${cwd:-$PWD}")
echo "⊡ ${project}  pid:${claude_pid}"

Wire it into settings.json

Add this block to ~/.claude/settings.json. If the file already exists, merge the statusLine key in — don't replace the whole file.

{
  "statusLine": {
    "type": "command",
    "command": "bash ~/.claude/statusline-ccs.sh"
  }
}

One-liner that does the merge safely (creates the file if missing, preserves existing keys, warns if a statusLine is already configured):

python3 - <<'PY'
import json, os, pathlib
p = pathlib.Path(os.path.expanduser("~/.claude/settings.json"))
data = {}
if p.exists():
    try: data = json.loads(p.read_text())
    except Exception: data = {}
if "statusLine" in data:
    print("statusLine already configured. Existing value:", data["statusLine"])
    print("Edit ~/.claude/settings.json by hand if you want to switch to the ccs statusline.")
else:
    data["statusLine"] = {"type": "command", "command": "bash ~/.claude/statusline-ccs.sh"}
    p.parent.mkdir(parents=True, exist_ok=True)
    p.write_text(json.dumps(data, indent=2))
    print("Added ccs statusline to ~/.claude/settings.json")
PY

Restart Claude Code after installing — the statusline only loads on session start. After restart, the bottom of your Claude Code window will look something like this:

┌──────────────────────────────────────────────────────────────┐
│ > your prompt here                                          │
│                                                              │
│                                                              │
│ ⊡ my-project  pid:54057                                      │
└──────────────────────────────────────────────────────────────┘

The number after pid: is what ccs add wants.

Stop Claude Code from auto-deleting your sessions

Important: Claude Code deletes local session transcripts after a retention period — cleanupPeriodDays in ~/.claude/settings.json, default 30 days. Once a transcript is deleted, ccs open can no longer resume that session: the name stays in your registry, but there is nothing left to resume. Extend the retention in the same settings.json:

{
  "cleanupPeriodDays": 3650
}

3650 days is ~10 years — set any number you like. One-liner that merges the key safely (preserves existing keys, skips if already set):

python3 - <<'PY'
import json, os, pathlib
p = pathlib.Path(os.path.expanduser("~/.claude/settings.json"))
data = {}
if p.exists():
    try: data = json.loads(p.read_text())
    except Exception: data = {}
if "cleanupPeriodDays" in data:
    print("cleanupPeriodDays already set:", data["cleanupPeriodDays"])
else:
    data["cleanupPeriodDays"] = 3650
    p.parent.mkdir(parents=True, exist_ok=True)
    p.write_text(json.dumps(data, indent=2))
    print("Set cleanupPeriodDays to 3650 in ~/.claude/settings.json")
PY

5. Add your first session (sample prompt)

Once the statusline is showing a PID, you have everything you need. Here are two ways to register your first session — pick whichever feels natural.

Option A — From a separate terminal

The ccs add command takes three arguments:

ccs add  <name>             <pid>    "<description>"
         │                  │        │
         │                  │        └── optional free text. Skip if you don't want one.
         │                  │           If omitted, ccs auto-fills it from the first
         │                  │           message of the session.
         │                  │
         │                  └── the number shown after `pid:` in your Claude Code statusline
         │                      (e.g. for `⊡ my-project  pid:54057`, this is `54057`)
         │
         └── a short kebab-case label you'll use to find this session later
             (e.g. `auth-refactor`, `mira-spec-review`, `inbox-zero`)

Open a new terminal tab (one that is NOT running Claude Code) and run:

# Replace 54057 with the PID shown in YOUR statusline.
# Arguments:  name              pid    description
ccs add       my-first-session  54057  "First test of ccs"

ccs list
# You should now see my-first-session listed as ● live

Option B — From inside Claude Code itself

Paste this prompt into the Claude Code session you want to register. It tells Claude to read its own PID from the statusline (by inspecting the running process) and register the session with ccs.

Register THIS Claude Code session with ccs.

STEP 1 — Resolve the PID of the Claude Code process you are running inside.

Try these methods in order, stop at the first one that returns a valid PID:

  a) Run: ps -ef | grep -E '[Cc]laude' | grep -v grep
     Pick the line whose `pwd`/cwd matches the current working directory.
     The second column is the PID.

  b) If (a) is ambiguous, list ~/.claude/sessions/*.json sorted by mtime
     descending and read each file's `cwd` field. Pick the one whose `cwd`
     equals the current working directory of THIS session. The filename
     (without .json) is the PID.

  c) If you still cannot resolve a PID with high confidence, STOP and ask
     the user to read it from the statusline at the bottom of the window
     (format: `⊡ <project>  pid:<number>`).

Never guess a PID. If two candidates exist, ask the user to disambiguate.

STEP 2 — Ask the user for a short name (kebab-case, e.g. `auth-refactor`)
and an optional one-line description. If no description is given, omit it —
ccs will auto-fill from the first message of the session.

STEP 3 — Register, via the Bash tool:

    ccs add <name> <pid> "<description-or-empty>"

STEP 4 — Confirm:

    ccs list

Print the output. The new row should show status `● live`.

STEP 5 — Show where the per-project registry was created or updated:

    <current-project>/.claude/claude-sessions-registry.md

Read the file and print its `## Registered Sessions` table so the user can
see the row landed.

Do not invent paths, PIDs, or descriptions. If any step fails, paste the
error and stop.

6. The per-project registry — auto-created, no manual step

The first time you run ccs add in a project, ccs creates <project>/.claude/claude-sessions-registry.md automatically using the template embedded in the script. After that, every ccs add, ccs remove, ccs rename, and ccs sync rewrites the table inside it. You don't copy a template by hand.

For reference, this is what gets written:

# Claude Code Sessions Registry

Name, list, and resume Claude Code sessions for this project without using `/resume`.
Global registry file: `~/.claude/named-sessions.json`

---

## Registered Sessions

> Auto-synced on every `ccs add`, `ccs rename`, `ccs remove`, and `ccs sync`.

| Name | PID | Status | Created | Last Used | Msgs | Description |
|---|---|---|---|---|---|---|
| — | — | — | — | — | — | No sessions registered for this project yet |
---

## Quick Reference

| Command | What it does |
|---|---|
| `ccs list` | Show all named sessions with live/idle status, created date, last used, message count |
| `ccs pids` | Show all running Claude processes with PIDs |
| `ccs open <name>` | Resume a session by name (run outside Claude Code) |
| `ccs add <name> <pid>` | Register a session using its PID (shown in the statusline) |
| `ccs add <name> <pid> "<desc>"` | Register with a custom description |
| `ccs update <name> "<desc>"` | Update description of an existing session |
| `ccs rename <old> <new>` | Rename a session |
| `ccs remove <name>` | Delete a session from the registry |
| `ccs sync` | Force-rebuild every project's registry table from the global JSON |
| `ccs sessions` | Browse last 30 sessions from history |

---

## Notes

1. `ccs open` must be run **outside** an active Claude Code session.
2. All other commands work both in terminal and inside Claude Code via `!`.
3. `○ idle` means the terminal process ended but the session is still resumable.
4. Session names are case-sensitive. Use lowercase kebab-case.
5. The Registered Sessions table is auto-maintained — never edit it manually. Run `ccs sync` if it looks stale.
6. Description is auto-populated from the session's first message if not provided.

7. Daily usage

Register a session

Look at the statusline of the Claude Code window you want to register. It shows the project name and a PID, e.g. ⊡ my-project pid:54057. From any terminal:

# Arguments:  name         pid    description (optional)
ccs add       my-session   54057
ccs add       my-session   54057  "Working on the auth refactor"

Or from inside Claude Code itself, prefix with !:

! ccs add my-session 54057

List, browse, resume

ccs list                    # all named sessions, live status, last used, message count
ccs pids                    # all currently running Claude PIDs
ccs sessions                # last 30 sessions from history (named or not)
ccs open my-session         # resume by name (run in a fresh terminal, outside Claude Code)

Maintain

ccs rename old-name new-name
ccs update my-session "Updated description"
ccs remove my-session
ccs sync                    # rewrite every project's registry table from the JSON

9. Troubleshooting

SymptomLikely causeFix
ccs: command not found ~/.local/bin not on PATH in this terminal. Open a new terminal, or source ~/.zshrc / ~/.bashrc. Confirm with echo $PATH.
Statusline doesn't appear after install Claude Code wasn't restarted, or statusLine wasn't merged. Quit and reopen Claude Code. Verify with cat ~/.claude/settings.json — you should see the statusLine key.
Statusline shows pid:1 or a wrong PID Claude Code launched the script via a wrapper that broke $PPID. Read the PID directly with ps -ef | grep -E '[Cc]laude' | grep -v grep and pass it to ccs add manually.
ccs add says No session file for PID <n> You passed a PID from a Claude Code process that hasn't created a session file yet (brand-new install, or first launch in progress). Send at least one message in the Claude Code session, then re-run ccs add. Or pass the full session ID instead of a PID.
Per-project registry file isn't created You registered by session ID instead of by PID — the script can only resolve the project from a PID. Re-register using the PID from the statusline. The session ID path is a fallback for when the PID's session file is missing.
ccs open can't resume an older session (name is in the registry, but nothing comes back) Claude Code auto-deleted the transcript — default retention is 30 days (cleanupPeriodDays). Set "cleanupPeriodDays": 3650 in ~/.claude/settings.json (see Section 4). Already-deleted sessions cannot be recovered — set this early.
Step 6 says "settings.json is invalid JSON" The file is malformed. Open it in an editor and fix the syntax (or move it aside as settings.json.bak), then re-run the bootstrap.
